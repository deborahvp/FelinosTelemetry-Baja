# ADR 0001 — MQTT over WebSocket/TLS through a managed broker for live telemetry

- Status: accepted
- Date: 2026-11-07

## Context

The team needs to watch the vehicle live from the pits during tests and competition (Baja SAE
México, Dec 2026). The first data source is a phone running Sensor Logger on a prepaid data
plan; later a custom ESP32 + LoRa board will feed the same system. The pit laptop and the
dashboard must work from any network, without opening ports or running a server.

## Decision

Sensor Logger publishes 1 s JSON batches over **MQTT on WebSocket + TLS (port 8884)** to
**HiveMQ Cloud** (free tier). Topic: `felinos/<deviceId>/<sessionId>`. Consumers subscribe to
`felinos/#`: the static dashboard (MQTT.js, read-only user) and the `felinos ingest` service
(paho-mqtt, NDJSON backup). Each client has its own credentials.

## Consequences

- No backend to host; works through mobile networks and NAT; TLS by default.
- Several consumers can listen at once; the future PCB gateway only needs to publish to the same broker.
- Depends on internet coverage at the track and on a third-party free tier (limits on
  connections and traffic). Mitigated by [ADR 0002](0002-local-recording-source-of-truth.md):
  the stream is never the only copy of the data.
- Dashboard credentials are visible to anyone who opens the page, so that user must be subscribe-only.
