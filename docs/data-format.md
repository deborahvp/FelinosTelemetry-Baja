# Data format

All times are **UTC nanoseconds since the Unix epoch** (int64), as produced by Sensor Logger.
Units are SI internally; conversion to g, km/h, ft and mph happens only for display and reports.

## Long schema (parser output)

| Column | Type | Example |
| --- | --- | --- |
| `time_ns` | int64 | `1793420456673332500` |
| `sensor` | str | `accelerometer` |
| `field` | str | `x` |
| `value` | float64 | `-0.612` |

`pivot_sensor(df, "accelerometer")` → `time_ns, x, y, z` (sorted, de-duplicated).

## Sensors

Names are the lowercase streaming names. CSV files are mapped to the same names
(`TotalAcceleration.csv` → `totalacceleration`).

| Sensor | Fields | Units | Notes |
| --- | --- | --- | --- |
| `accelerometer` | x, y, z | m/s² | **Gravity removed** (= `totalacceleration` − `gravity`) |
| `totalacceleration` | x, y, z | m/s² | Includes gravity |
| `gravity` | x, y, z | m/s² | Android: points **up** (≈ +9.8 on the axis facing the sky) |
| `gyroscope` | x, y, z | rad/s | |
| `orientation` | qw, qx, qy, qz, roll, pitch, yaw | –, rad | |
| `location` | latitude, longitude, altitude, speed, bearing, horizontalAccuracy, verticalAccuracy, speedAccuracy, bearingAccuracy | °, m, m/s, ° | ≈ 1 Hz; `speed` < 0 = invalid |
| `barometer` | pressure, relativeAltitude | hPa, m | |
| `compass` | magneticBearing | ° | |
| `battery` | batteryLevel, batteryState | 0–1 (or %) | To confirm on Android |
| `*uncalibrated` | x, y, z | as calibrated | |

Phone axes (Android and iOS): x → right edge of the screen, y → top edge, z → out of the screen.

Platform conventions differ: Android reports gravity pointing **up** and linear acceleration in
the direction of motion, in m/s²; raw iOS (Core Motion) reports gravity pointing **down**, linear
acceleration with the opposite sign, and may use g instead of m/s². The dashboard detects both
(gravity sign against the mounted vertical axis, gravity magnitude for units).

## MQTT message (confirmed with a real capture)

```json
{"messageId": 9, "sessionId": "c886864a-…", "deviceId": "02a84114-…",
 "payload": [{"name": "accelerometer", "time": 1794032705001959400,
              "values": {"x": -1.05, "y": 1.57, "z": 1.45}}]}
```

- One message per batch period (1 s). `messageId` increments per session (gaps = lost messages).
- `time` exceeds 2⁵³: exact in Python, rounded to ~256 ns in JavaScript (irrelevant for display).

## CSV export

A zip (or folder) with one CSV per sensor: columns `time, seconds_elapsed, <fields…>`, plus
`Metadata.csv` (device, app version, `recording epoch time` in ms, timezone, sensors, sample
rates) and `Annotation.csv` (may be empty).

If a spreadsheet re-saved a file, `time` becomes `1.79342E+18`. The parser then rebuilds it as
`recording_epoch_ms × 10⁶ + seconds_elapsed × 10⁹` (error < 1 µs).

## NDJSON stream backup

One file per `sessionId` in `data/stream/`. Each line:

```json
{"received_at": 1794032706100000000, "topic": "felinos/<device>/<session>", "message": {…}}
```

Invalid payloads are kept as `{"message": null, "raw": "<text>"}`.
